# The gate inventories every live mention, under `Jaune/` and in `Main.lean`,
# of a gas constant that a supported fork reprices and that therefore lives in
# `ForkRules.gas` as rule data: `gasColdAccountAccess`, `gasCallValue` and
# `gasCreate` (programme D2). Each is shadowed by a `GasSchedule` field the
# interpreter must read instead -- `coldAccountAccess`, `callValue`,
# `createAccess` -- and each still exists as a global because Prague's value is
# the legacy one and several Prague-specific statements are about it.
#
# Every occurrence must match an exact, line-number-independent row below:
#
#   <relpath> <source line, trimmed, whitespace runs collapsed>
#
# A new occurrence anywhere -- in an instruction site, a charging helper, or a
# new lemma -- fails the gate until it is classified here. That is the point:
# once `BenvStat` carries a `Fork`, every reachable machine's legacy-lane
# schedule is `pragueGasSchedule`, whose three numbers equal these globals by
# `rfl`, so a site that read the global instead of the selected record would
# compute the same number on every machine and no evaluation guard could see
# the difference. This inventory is what sees it.
#
# Goal `jaune-forks-by-construction-v1`, decision D-F6 (iii). It replaces the
# structural half of the retired `meteringGuardLegacyRules` machine guards; the
# arithmetic half survives as the schedule-level rows beside
# `meteringGuardLegacySchedule` in `Jaune/Execution.lean`.
