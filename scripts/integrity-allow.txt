# Semantic-integrity allowlist for scripts/check-integrity.sh.
#
# Owned by ~/plans/integrity.md. Generated from `scripts/check-integrity.sh
# --list` at the arc's branch point (Jaune b0dc4ee) and then classified by
# hand. Every row is an exact, line-number-independent normalised
# occurrence:
#
#   <rule> <relpath> <source line, trimmed, whitespace runs collapsed>
#
# followed by `## <disposition>`. Two dispositions exist:
#
#   KEEP(wrapper=..., theorem=...)
#       a retained optimized operation, permanently allowed because a named
#       checked/fixed-size wrapper and a named bounds or size theorem
#       discharge it. Both names must be real declarations.
#
#   PENDING(step<N>,<mode>) <why>
#       a known defect this arc removes. `mode` says how it is
#       discharged: `remove` (the operation disappears), `wrapper` (it
#       survives behind a proof-carrying interface and the row becomes a
#       KEEP row naming that interface), `proof-indexed`, `totalize`, or
#       `match`. Every PENDING row is reported on every run.
#
# There is deliberately no R1 row and there never may be: absence of
# `partial def`, `implemented_by`, and `dbg_trace` is asserted outright,
# per ~/plans/silence.md having removed the last of each. The gate refuses
# an allowlist that carries an R1 row at all.
#
# The budget below is the number of PENDING rows. It may only shrink. A
# step that discharges a row deletes it (or rewrites it as KEEP) and
# lowers the budget in the same commit.
#
# pending-budget: 92
#
# At the branch point nothing was discharged: Step 1 inventories, it does
# not repair. The KEEP rows below are Step 8's, and they are all the BLAKE2b
# compression kernel: see the Step-8 note at the end of this header.
#
# ---------------------------------------------------------------------------
# AUDIT NOTE, recorded by Step 1 and binding on Steps 7 and 8.
#
# The Step-1 audit REFUTED the planning-time premise that the optimized crypto
# kernels are `private`. NONE of the bang-operation sites in the closure sits
# inside a `private` declaration. Jaune/Precompiles.lean and Jaune/BLS.lean
# contain zero `private` declarations at all, and Jaune/Hash.lean's only two
# (`rolc`, `round1600`) contain no bang operation. The keccak / SHA-256 /
# RIPEMD-160 / Blake2 kernels are public `Jaune.KECCAK.*`, `Jaune.SHA256.*`,
# and `Jaune.Blake2.*` names reachable by any downstream importer. They are
# internal by convention only.
#
# ~/plans/integrity.md P0.6 fix item 4 permits "a private optimized array
# kernel behind a checked wrapper". Step 8 must therefore either make these
# declarations private or give them fixed-size (`Vector`/structure) inputs. It
# may not merely attach a wrapper and leave the raw kernel exported, because an
# exported raw kernel is exactly the "public helper that currently accepts an
# arbitrary short array" the plan requires to be rejected or totalized.
#
# Not every row below is a live hazard, and the difference drives Step 8's
# effort allocation:
#
#   - `Array.set!` is `Array.setIfInBounds` in Lean core: TOTAL, a silent
#     no-op when out of range. It never panics. The objection to it is
#     allocation cost and an unexpressed invariant, not partiality.
#   - `a[i]!`, `ByteArray.get!`, and `Option.get!` DO panic: they print to
#     stderr and return `default`.
#   - `Jaune.List.slice!` (Jaune/Basic.lean:410) is total despite its name;
#     it zero-pads through `takeD`.
#
# The one genuinely unguarded, reachable, attacker-influenced site the audit
# found is `jumpable` (Jaune/Machine.lean:2393): `cd.get! k` where `k` is a
# popped stack value with no bound relative to `cd.size`. An out-of-range JUMP
# therefore emits a real `panic!` line on stderr and returns `default = 0`;
# the verdict stays correct (0 is not JUMPDEST, so InvalidJumpDestError), but
# the partial read is live on a consensus path. By contrast `noPushBefore`
# (:2384) and `ByteArray.getInst` (:1405) are both guarded by an explicit
# `< size` test, and both `Option.get!` sites (Execution.lean:108 delegation,
# Transaction.lean:1053 system-call error) are guarded by a validity/isSome
# test immediately above. Step 7 owns all of these.
#
# DISCHARGED by Step 7 (2026-07-31): the fakeExpAux fuel panic is gone — the
# loop is a well-founded recursion with recurrence/uniqueness theorems and the
# scripts/check-fake-exp.sh differential oracle; jumpable carries the missing
# bounds test (OOB destination is semantically false); noPushBefore and
# ByteArray.getInst read through their existing tests with proof-indexed
# access; the four simple projections are total matches/head? reads.
#
# DISCHARGED by Step 8 (2026-08-01): all 152 crypto/helper rows are gone or
# rewritten KEEP, and the closure now holds no explicit abort at all.
#
#   - Jaune/Hash.lean (91 rows, deleted). `KECCAK.Array.modify!` and its
#     out-of-bounds branch no longer exist. Keccak's state is a
#     `Vector UInt64 25`, SHA-256's schedule a `Vector UInt32 16` under a
#     round budget `n <= 64`, RIPEMD-160's tables `Vector`s with `Fin 16`
#     permutation entries. The reference transcription is polymorphic over the
#     25-lane vector and needs no `Inhabited` fallback; `KECCAK.piln_lt`
#     decides that every pi-table entry names a lane. Ranged
#     `ByteArray.keccak` carries `loc + sz <= bs.size` into the sponge and
#     materialises the zero extension once when it does not hold.
#   - Jaune/EC.lean (4) and Jaune/BLS.lean (6), deleted. Coefficients are read
#     through `List.takeRightV`, which pads on the left to a fixed width. For
#     BN254's `twist` that also CORRECTS the arithmetic on a trimmed
#     coordinate; the three BLS sites were already padding and only gain the
#     proof.
#   - Jaune/Basic.lean (5, deleted). `Bytes.toUInt16` reads through
#     `Bytes.packV`; `ByteArray.sliceD` reads through its own bounds test;
#     `List.splitToArray.aux` carries `idx + sz = array.size` and writes with
#     `Array.set`; `Array.copyD` writes with the total `Array.setIfInBounds`
#     and owes `Array.size_copyD` for the length half of its contract.
#   - Jaune/Precompiles.lean (46 rows -> 43 KEEP). The BLAKE2b kernel is
#     frozen by ~/jaune/scripts/report-integrity-design.md §9 and is NOT
#     reopened: `Blake2.g`/`round`/`rounds` are the reference the equivalence
#     theorems are stated against, and `Blake2.roundVec`/`roundsVec` are the
#     unboxed implementation those theorems cover. What Step 8 added is the
#     checked wrapper the plan requires around them, and made them `private`
#     so the only way in is through it: `bCompress` now REJECTS a
#     chaining value that is not eight words or a message that is not sixteen,
#     rather than padding it, and builds the working vector from
#     length-indexed inputs. `length_readLeUInt64Words` is why the
#     precompile's 213-byte check always satisfies that; `blake2Sigma_size`,
#     `size_blake2Sigma_row`, `size_blake2Sigma_get` and `blake2Sigma_lt`
#     decide the table facts the kernel's indexed reads rest on. Every KEEP
#     row below names that wrapper and one of those theorems.
# ---------------------------------------------------------------------------
